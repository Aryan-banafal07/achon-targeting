02

How the pipeline fits together

Three stages run as one continuous chain. Each stage’s output table is the next stage’s input, so a re-run anywhere upstream requires re-running everything below it.

Stage 1 HCP Universe Build Thirteen extracts validated on NPI, resolved to one specialty and one name per HCP, scored on a three-source engagement decile, then classified into an interim tier 1–4. → hcp_universe_updated_v6
Stage 2 Target Tier Assignment A patient cohort is built, treatment status attached, and an 8-cycle cascade picks one primary HCP per patient. Patient evidence then converts the static tier into a field-ready target tier 1–5. → hcp_universe_updated_v7
Stage 3 Accounts & Field Workload The target universe is frozen for reproducibility, rolled up to mastered accounts, clustered into priority tiers P1–P4, then enriched with affiliation, specialty and territory to size call capacity. → account_rollup · v10 · workload_index

One naming caution. Three different scales are informally called “tier”: tier (Stage 1, 1–4, specialty and decile), target_tier (Stage 2, 1–5, patient evidence) and priority_tier (Stage 3, P1–P4, account grain). Always reference the fully-qualified column name.

03

Building the universe

Every source is validated on a 10-digit NPI before use, then full-outer-joined so an HCP present in any single source is retained. The build moves through six numbered versions — a genuine sequence, each one adding a single decision.

  • v1  join + specialty + name
  • v1+  VOD patch & manual adds
  • v2  treater flag
  • v3  noise pruning
  • v4  decile scoring
  • v5  cleanup + Q77.4 flag
  • v6  tier 1–4

Komodo is read from a frozen snapshot rather than the live feed, so the build stays reproducible between runs.

04

Deciling & initial tiering

Three independent deciles are computed — one per claims source — and the best of the three is kept, so an HCP gets credit for whichever source shows the strongest relative engagement.

How the decile is built

  • Veeva decileQ77.4 patients + claims
  • Komodo decileQ77.4 claims + patients
  • DHC decileQ77.4 Mx + patients
  • final_decileGREATEST of the three

Each metric is normalised to a share of its column total, ranked descending, and mapped to a 1–10 band on cumulative share. HCPs with volume floor at decile 1; HCPs with none sit at 0.

Initial tier rules — first match wins

Tier 1 KOL/QED flagged or known treater or decile ≥ 5 and Ped Endo/Geneticist
Tier 2 Decile < 5 Ped Endo/Geneticist or decile ≥ 8
Tier 3 Decile ≤ 7 and generates Q77.4 claims or decile 5–7
Tier 4 Fallback — none of the above

No HCP generating a Q77.4 claim lands in the bottom tier, and no Ped Endo or Geneticist falls below Tier 2 — both QC gates confirmed on the refreshed build.

05

Patient attribution & target tiers

Specialty alone doesn’t earn a field call. This stage layers in who each HCP is actually attributed to, and how many patients they have genuinely touched.

Patient cohort

  • Q77.4 arm≥1 office E&M + ≥2 dates
  • Voxzogo arm≥1 Vox / vosoritide fill
  • Age scope2–18 years
  • Treatment statusActive / Discont. / Never

Attribution cascade — lowest cycle wins

  1. Tier 1/2 Ped Endo or Geneticist, qualifying visit
  2. Vox prescriber, gated on a qualifying visit
  3. Tier 1/2, other specialty
  4. Tier 3/4
  5. Tier 5
  6. Visited HCP outside the universe
  7. Vox-prescriber stop-gap — not visit-gated
  8. Incidence-treater stop-gap — last resort

A rendered 3-year Q77.4 visit is required for any attribution — a Voxzogo fill alone no longer qualifies. Ties within a cycle break on office E&M visits first, so a clinician who actually sees the patient in clinic outranks high-frequency home-health billing.

06

Affiliation, account rollup & prioritization

Before any rollup, the target universe is frozen at 3,173 HCPs. Komodo claims change over time, and without that lock, target counts and every downstream account number would drift between runs.

HCP → account affiliation

Accounts resolve from a single mastered NPI-to-account table — the earlier name-matching crosswalk is retired, and placeholder values are converted to true nulls so an HCP with no genuine affiliation is excluded rather than grouped under a dash.

  • Targets without a mastered HCO351
  • Recovered by fuzzy match + manual+178
  • Still unmapped173

Priority tiering method

Signal-bearing accounts are clustered with k-means on log-scaled opportunity and quality features, ranked by mean signal. Accounts with no signal at all skip clustering entirely.

Three deterministic floors then run in order, and the result is frozen so future rollups restore the locked tier rather than re-clustering and drifting.

07

Field workload index

The last step converts target tier and engagement decile into a single number that sizes each HCP’s fair share of the field’s fixed call capacity.

workload_index  =  (calls ÷ Σcalls) × 0.7 × 32,000
               +  (final_decile ÷ Σdeciles) × 0.3 × 32,000

Calls by tier

  • Tier 118 calls
  • Tier 216 calls
  • Tier 312 calls
  • Tier 4 & 5excluded

Weighting & capacity

  • Total call pool32,000
  • Tier-based call share70%
  • Engagement decile share30%
  • Eligible HCPs3,173

Geography

Each HCP resolves to one ZIP through a source waterfall, then maps to a state and territory via the ZIP-to-territory reference table — so workload can be balanced and compared by geography.
